# DataHealth AI — Phase 6: Local Clinical-Document RAG

**Goal:** Search synthetic Synthea clinical documents using Ollama embeddings + ChromaDB, then summarize with a local Qwen LLM. All code and technical artifacts are in English.

## What to copy into the existing project
- `src/rag_assistant.py` → `src/`
- `tests/test_rag_assistant.py` → `tests/`
- `docs/rag_architecture.md` → `docs/`
- `requirements_phase6.txt` → project root
- This `README_PHASE6.md` → project root

Do not replace your current `src/clinical_assistant.py`, Gold database or existing files.

## Requirements
- Working Gold SQLite database: `data/gold/datahealth.db`
- Existing Silver clinical documents: `data/silver/fhir/clinical_documents.csv`
- Local Ollama running on `http://127.0.0.1:11434`
- `qwen3.5:4b` already installed in Ollama
- An *additional embedding model* (`nomic-embed-text`) installed in Ollama
- `chromadb` Python package

### Windows PowerShell commands
From your project root:

```powershell
python --version
ollama pull nomic-embed-text
python -m pip install -r requirements_phase6.txt
```

If Chroma dependencies fail to install with an experimental Python 3.15 build, use Python 3.12 (or 3.13) with a virtual environment:

```powershell
py -0p
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements_phase6.txt
```

If PowerShell blocks activation, run `.\.venv\Scripts\python.exe -m pip ...` and `.\.venv\Scripts\python.exe -m src.rag_assistant ...` instead. Creating a fresh venv does not alter your existing Python installation.

## Build the vector index
```powershell
python -m src.rag_assistant index --silver "data/silver/fhir" --database "data/gold/datahealth.db" --index-dir "data/vectorstore/chroma" --reports "reports/rag"
```

This command reads Silver documents, cross-checks them in Gold, requests local embeddings, and stores vectors in Chroma. It writes `reports/rag/rag_index_summary.json`. The expected **candidate document count** from the previous audit was **112**, but the actual count must be checked in the generated report. The number of chunks will depend on text length.

**Index rebuild:** after changing the dataset or embedding model, add `--rebuild` to the indexing command. This replaces only the named Phase 6 Chroma collection.

## Search without LLM generation (first test)
```powershell
python -m src.rag_assistant search --patient-id "e34fa1e8-0cbc-0d22-89d4-6996de874bd8" --question "What does the most recent clinical note say about medications?" --top-k 3
```

The result contains patient metadata, retrieved passages, document IDs, dates and source markers. No chat model is called.

## Generate a grounded answer
```powershell
python -m src.rag_assistant ask --patient-id "e34fa1e8-0cbc-0d22-89d4-6996de874bd8" --question "Summarize the patient's latest clinical note and cite the source." --top-k 3
```

The answer is generated by Qwen using the retrieved passages only. Compare its assertions to the `search` output; a successful response is not proof of factual or clinical correctness.

## Run tests
```powershell
python -m unittest discover -s tests -p "test_rag_assistant.py" -v
```

Unit tests use a simulated vector database and mocked Ollama responses, so they do not require installed Chroma or a running model. Live Chroma and Ollama functionality must be validated locally.

## Files generated locally

## Security note
Use synthetic data only. Never index real patient records without approved governance, access-control enforcement, proper consent/legal basis, confidentiality safeguards and relevant security audits.
